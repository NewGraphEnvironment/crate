## Critical correction: canonical shape is WIDE, not long

My initial issue body (crate#2 v1) sketched long-canonical for `user_habitat_classification`. Plan-mode exploration with three parallel Explore agents surfaced that this was wrong on every available signal.

### Evidence for wide-canonical

| Source | Evidence |
|---|---|
| Current upstream CSV | `link/inst/extdata/configs/default/overrides/user_habitat_classification.csv` (synced 2026-04-27, upstream sha `40c4a0a`): wide format, one row per (blue_line_key × species_code), separate integer cols `spawning`, `rearing`. 15,632 rows × 11 cols. |

| link SQL schema | `link/R/lnk_pipeline_prepare.R` lines 170-177: `CREATE TABLE ... user_habitat_classification (blue_line_key integer, downstream_route_measure double precision, upstream_route_measure double precision, watershed_group_code text, species_code text, spawning integer, rearing integer)` — wide. |
| link consumption | `link/R/lnk_pipeline_classify.R`: calls `frs_habitat_overlay(species_col = "species_code", habitat_types = c("spawning", "rearing"))` — expects separate spawning/rearing cols (wide). |
| Old long format (pre-2026-04-26) | git commit `9cc30fc`: long format with `habitat_type` text + `habitat_ind` text. This is the historical variant adapter must recognize and pivot to wide-canonical. |

### Implication

- **Adapter wide-input path:** identity passthrough after schema validation
- **Adapter long-input path:** pivot_wider to wide-canonical (preserves -4 excluded values; emit wide row per (segment × species), populate spawning/rearing integer cols based on long input's habitat_type + habitat_ind)
- **Issue body needs update post-merge** (Phase 9): replace "long-canonical" everywhere; update schema YAML format example

## Special value `-4` semantics

Some rows have `spawning = -4` or `rearing = -4` meaning "excluded / not applicable" (e.g., mining-altered streams). The adapter MUST preserve this value rather than coercing to 0 — it carries semantic meaning downstream consumers need.

When pivoting from long to wide: if long row has `habitat_ind = "?"` or similar excluded marker, emit wide row with `spawning = -4` (or `rearing = -4`). Long format pre-2026-04-26 used `habitat_ind = "t"` / `"f"` strings; need to check if long format ever encoded the -4 case.

For the synthetic test fixtures, include at least one -4 row to exercise this preservation path.

- `bcfp` source code (matches link's existing CSV file-prefix convention; cabd/dfo files all sync from bcfishpass upstream so they're `source = "bcfp"` with file_name preserving the cabd/dfo prefix)
